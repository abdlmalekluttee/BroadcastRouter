# P2-20 Audio Detector Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan inline with TDD. Steps use checkbox syntax for tracking.

**Goal:** Warning bursts cannot become audio failures without elapsed failed PCM advancement, and recovered sessions cannot retain an obsolete failure latch.

**Architecture:** Reuse P2-22's monotonic, independently measured PCM evidence and two-second Healthy qualification instead of another warning-count timer. Keep raw stderr/anomaly history, but separate historical diagnostics from current recovery evidence. The coordinator's two-independent-signal gate remains authoritative.

**Tech Stack:** .NET 8, xUnit, real fake-child processes and private observation pipes.

**Spec:** Owner Phase 2 plan section 4/P2-20 and accepted Phase C order; private original plan remains outside git. Base is P2-22 commit `4b87ce2` (draft PR #75).

## Global Constraints

- Production stays read-only; no hardware, deployment, service or routing actions.
- One task branch/PR; only the owner merges. Do not modify frozen PR branches.
- Preserve correctness assertions; promote both unchanged R04 probes in the fixing commit and remove only their strict registry entries.
- No amplitude-based silence detector, new GUI setting, GPU work or media-framework rewrite.
- Unknown measurements never mean failed PCM. Digital silence with advancing samples remains healthy.
- P2-22's provisional suspect 1s + confirmation 3s, startup 20s and recovery 2s remain unchanged and bench-unqualified.

## Review Focus

1. Several diagnostics from one packet or the same instant must not accumulate recovery votes; cover burst sizes and unrelated diagnostic text.
2. Continuous digital silence and short decoder glitches must remain healthy when samples advance; cover failed-to-Suspect-to-Healthy recovery.
3. Missing instrumentation, generated silence and invalid sample metadata must not supply a failed input-audio vote.
4. A late stderr write racing a snapshot must not be cleared by a stale read of an older failure; compare-and-clear only the observed record.
5. A genuinely failed decoder still needs bounded corroborated recovery, including publisher hold; retain P2-22 positive recovery cases.

## Pre-flight rulings

Warning text has no reliable packet identity. Do not invent one from stderr line count or address text. Removing count-based authorization makes repeated same-packet diagnostics idempotent policy input; raw transcript/anomaly counts are still retained for diagnosis. Reuse P2-22's elapsed-media/hysteresis model rather than adding a competing timer. Cost: unsupported instrumentation remains Unknown and cannot prove audio failure; qualification remains an explicit gate.

Explicit recovery authorization still belongs to the shared two-signal coordinator gate; a detector category is context, not an independent failed signal. P2-21 retains the video-policy task boundary. No modification of audio resampling or output flags is planned.
