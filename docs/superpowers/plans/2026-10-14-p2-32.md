# P2-32: inherited helper containment

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans inline, with test-driven-development and one fresh whole-branch review.

**Goal:** A crashed server leaves no owned media/helper process behind, without killing unrelated processes.

**Architecture:** Enrol the host in a private, non-inheritable kill-on-close Windows job before any media/helper launch. Children inherit membership at process creation; keep existing scoped supervisor jobs nested underneath. The lifetime handle is retained until OS process termination, never closed by route cleanup or graceful-shutdown callbacks.

**Tech stack:** .NET 8, Windows job objects, existing ProcessStartInfo.ArgumentList, xUnit and real synthetic child executables.

**Spec:** Phase 2 strict fix plan P2-32/R14, plus the owner's Phase D authorization. Hardware, production mutation and merge remain outside this task.

## Global constraints

- One main-based PR; failing tests first; owner alone merges.
- Keep all 136 legacy behavioural tests. R18 remains open for Phase G.
- No native command-line/stdout launcher rewrite, shell invocation, breakaway flags or process-name kills.
- Failed containment refuses launch. Never enrol an unrelated existing process.
- Windows service/Session 0 and real DeckLink qualification remain separate.
- The root lifetime job must NEVER be disposed while the host runs.

## Review focus

1. Host termination between CreateProcess and scoped-job assignment: inheritance must already contain the child.
2. A child retaining/inheriting the root job handle could defeat kill-on-close; prove the handle is non-inheritable.
3. Scoped supervisor disposal must not kill the host or unrelated helper owners.
4. Parallel first launches and short-lived successful children must not fail containment or leak handles.
5. Preview/probe cancellation, pending pipe reads and descendant handles must not leave unbounded cleanup.
