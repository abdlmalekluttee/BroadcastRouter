# P2-32: atomic per-helper containment

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans inline, with test-driven-development and one fresh whole-branch review.

**Goal:** A crashed server leaves no owned media/helper process behind, without killing unrelated processes.

**Architecture (corrected after reproduction):** Create each helper suspended with an atomic Windows JOB_LIST assignment and an explicit standard-handle allowlist. Retain an exact managed process handle before resuming. Per-helper kill-on-close jobs contain descendants even if the parent exits; parent exit closes the job before draining pipes. Keep existing higher-level supervisor ownership unchanged.

**Tech stack:** .NET 8, Windows job objects, existing ProcessStartInfo.ArgumentList, xUnit and real synthetic child executables.

**Spec:** Phase 2 strict fix plan P2-32/R14, plus the owner's Phase D authorization. Hardware, production mutation and merge remain outside this task.

## Global constraints

- One main-based PR; failing tests first; owner alone merges.
- Keep all 136 legacy behavioural tests. R18 remains open for Phase G.
- No shell invocation, breakaway flags or process-name kills. Tokenized arguments use Windows CRT quoting, never a shell. Anonymous pipes use managed stream wrappers, never private Process-field injection.
- Failed containment refuses launch. Never enrol an unrelated existing process.
- Windows service/Session 0 and real DeckLink qualification remain separate.
- Only a helper is a member of its job; the host and sibling owners must never be enrolled.

## Review focus

1. Host termination during launch: JOB_LIST must assign membership before child execution; native process and thread handles close on every failure path.
2. Standard HANDLE_LIST excludes other host handles; the job handle is non-inheritable and cannot keep itself alive.
3. Per-helper disposal/parent exit must clear descendants without killing the host or sibling owners. Explicit forced exit remains -1, not success0.
4. Parallel and short-lived launches preserve tokenized argv, environment, working directory, encoding, hidden windows and pipe ownership.
5. Preview/probe cancellation, pending pipe reads and descendant handles must not leave unbounded cleanup. Check partial allocation, cancellation, repeated disposal and denied native launches.
