# Phase A Foundation Implementation Plan

> **For agentic workers:** Use executing-plans inline, with an independent
> requesting-code-review reviewer before EACH task PR as the owner requires.

**Goal:** Establish trustworthy delivery, deterministic regression harnesses and
session-level evidence without changing recovery thresholds or production.

**Architecture:** Keep Domain/Application/Infrastructure/Web responsibilities.
Discovery and probes qualify input; reservations own outputs; the coordinator
supervises owned processes and persists intent. Phase A instruments those
boundaries rather than redesigning their decisions.

**Tech Stack:** .NET 8, Windows, PowerShell, GitHub Actions, standard dotnet test.

**Spec:** Owner-provided Phase 2 Fix Plan and approved conditions; the operational
source/evidence bundle remains internal. The public constraints are recorded in
PHASE2_PROGRESS.md, not copied from private evidence.

## Global Constraints

- Production stays read-only. No hardware tests in Phase A.
- One PR per P2 task; human-only merge; no force pushes or direct main pushes.
- Failing test commit precedes implementation. Preserve all 136 baseline tests.
- KnownDefect tests assert correct behavior; CI validates the exact expected
  assertion failure and rejects crashes, missing tests and unexpected passes.
- No watchdog/retry threshold changes, new UI knobs, GPU or framework rewrite.
- No operational evidence, credentials, binaries or proprietary assets in PRs.
- Stop at Gate A; later phases require the owner's continue instruction.

## Review Focus

- Manifest overwrite/path escape: reject without replacing an existing file.
- False qualification claims: missing FFmpeg identity cannot mean qualified.
- Unexpected KnownDefect outcome: strict result validation, never skip or invert.
- Refactor masking a policy change: compare all 136 plus seven probes pre/post.
- Telemetry disk/secret pressure: bounded writes, redaction before persistence.
