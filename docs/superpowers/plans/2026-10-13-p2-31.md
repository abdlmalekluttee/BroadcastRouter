# P2-31 Bounded persistence implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Each behavior starts with a failing test, then implementation and a green suite.

**Goal:** Diagnostic/lifecycle bursts or slow storage must not block media callbacks, accumulate unbounded tasks, or falsely acknowledge durable routing state.

**Architecture:** Keep essential settings/routes/audit writes awaited and transactional. Move only diagnostic/lifecycle log writes into a bounded coalescing worker with observable queue age, loss and transaction latency. Retain telemetry's sticky durable loss marker but checkpoint repeated loss counters at barriers rather than fsync every eviction. Add bounded database diagnostic retention.

**Tech Stack:** .NET 8, SQLite, xUnit, real local fake children, supervision clock.

**Spec:** Approved Phase 2 P2-31/R12 and owner correction requiring reproduced/root-caused telemetry flush timeout before Gate D. Private evidence remains outside git.

## Global constraints

- One PR from merged main, owner alone merges; no production connection/change or hardware for this task.
- No test removal, timeout increase or policy weakening. R18 remains open for Phase G.
- Essential state acknowledgement means committed transaction, never queue admission. Diagnostics cannot authorize recovery.
- Telemetry retains the 10 GB cap and max(20%, 20 GB) disk reserve, sticky loss alarm and foreign-file protection.
- No unbounded queued Tasks; bounded queue and worker, bounded shutdown, no async-void.
- P2-30 is a separate PR; preserve its shutdown/admission and guard integration when the owner combines changes.

## Review focus

1. Crash between first early eviction and the next counter checkpoint: loss remains durably visible, not a healthy restart.
2. Busy SQLite plus a storm of distinct child IDs: callbacks remain bounded, queue capacity enforced, loss visible, no pending task per event.
3. Partial transaction/disk failure: failed essential state cannot be published or reported saved.
4. Flush/cancellation while a coalesced record is in flight: a barrier covers prior admissions, not unrelated future arrivals; no disappearing waiter.
5. Retention overlaps readers/writers: bounded batches, no configuration/current-route/audit deletion, no foreign-file deletion.
