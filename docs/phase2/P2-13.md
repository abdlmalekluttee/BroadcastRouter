# P2-13 — measured graceful shutdown (software candidate)

Scope: owned FFmpeg stop/handoff and transcript draining. No production mutation,
hardware use, native FFmpeg patch or driver change. Physical acceptance is OPEN.

## Proven causes and changes

- The handoff path silently replaced the configured graceful deadline with 750 ms.
  A synthetic child that acknowledges `q` and exits after 1,100 ms is killed at
  767.1 ms, even with a configured three-second budget. Normal stop succeeds.
  Handoff now uses the same configured budget. It is a maximum wait, not a sleep;
  cooperative exits still complete immediately. The default is not retuned from
  fake-child measurements. Physical p99 plus margin remains a bench requirement.
- Drain cancelled both readers on entry, before EOF. A controlled pending-reader
  test proves premature cancellation. Drain now waits for EOF up to the existing
  five-second I/O guard, then cancels a stuck reader and records incompleteness.
- A pipe-reader exception escaped drain and prevented exit reporting/disposal.
  An injected IOException reproduces it. The error is redacted and retained;
  cleanup continues after OS exit. This is not permission to release a live owner.
- Per-session `OwnedProcessStopPhase` records include monotonic duration, phase
  budget, result, exact PID/start/session identity for quit signal, exit wait,
  forced reap and pipe drain. A successfully written `q` is **not** an ACK from
  FFmpeg; OS exit remains the definitive release evidence. Telemetry cannot prove
  physical SDI silence or that a driver has released all buffers.

Kill-on-close containment, exact-owned process-tree termination, cancellation
cleanup, reap limits and owner serialization remain in place. No global PID/name
kills. Media health thresholds and all seven KnownDefect assertions are unchanged.

## Outstanding acceptance and risks

- No measurement yet of custom `win_safe_terminate` execution or DeckLink buffer
  release. Source patch/build qualification belongs to P2-40/41; its behavior on
  the assigned bench must still be measured for this task.
- Do not attribute all 92,342 historical forced terminations to the 750 ms limit:
  the new phase records are needed to distinguish blocked quit, OS exit latency,
  pipe retention and genuinely noncooperative processes.
- Configured timeout may lengthen a formerly forced handoff. This trades an
  unqualified fast kill for the already configured graceful budget, not seamless
  switching. Bench qualification must select p99 plus margin and measure off-air
  time. Five-second reap/drain guards remain bounded but are not yet qualified.
- Required physical 500 cycles (<1% forced), zero orphans, released port within
  deadline and no ghost audio remain OPEN. Production stays unchanged.
