# P2-11 — retain fallback during offline recovery

## Reproduction and cause

The first task commit (78d38a8) asserts correct behavior through the actual
RouterCoordinator and a real owned fake child. It fails because a due retry stops
the healthy fallback before opening the known URI. A failed/404 input can thus
reopen the same DeckLink output repeatedly without any evidence of media readiness.

The second test-only commit adds probe-policy contracts. Subsequent focused red
tests exposed discovery bypassing recovery cadence, a stale queued media-mode
restart bypassing qualification, missing simulation decoded-audio evidence, and
disabled/unvalidated outputs being handed off. Assertions were not weakened.

## Change

- Recovery polls one asynchronous FFprobe request per recovering source, with
  1/2/5/10/20/30-second capped failure delays. It never opens DeckLink.
- Failed, cancelled, stale or generation-mismatched probes retain the exact fallback
  owner. For saved recovering routes, discovery retains publisher observations and last-known tracks,
  but delegates probing to this single recovery cadence. Automatic routes retain
  their existing discovery path so that they can become ready and recover.
- Require decoded video and decoded audio for expected tracks, not audio packet
  counts. Audio-led and video-only routes qualify only their expected tracks;
  previously unknown tracks are inferred from decoded probe evidence.
- A two-second proof is consumed once. Recheck it after acquiring the output gate,
  plus output eligibility, lease, tools, source URI and preset configuration. Reap
  the old owner before starting the replacement. Failed validation keeps fallback.
- Explicit operator-forced restart remains explicit; it is not an automatic retry.
- Structured decision telemetry records probe and handoff outcomes. In-memory
  configuration equality tokens may contain the URI but are never logged/persisted.

## Software evidence (not physical qualification)

| Scenario | Before | After |
|---|---|---|
| First due retry while offline | Stops working fallback | Same PID/session; zero stop requests |
| 24 h simulated offline, actual coordinator + fake child | First retry violates retention | One original fallback start, zero restarts/stops |
| 24 h immediate 404 responses, injected policy clock | No independent probe gate | Exactly 2,884 probes; zero handoffs |
| New decoded AV from a real fake probe process | Opens before qualification | Exactly one serialized old-exit/new-start handoff |
| Publisher flap while waiting for output gate | Stale proof could stop fallback | Original owner retained |
| Discovery and stale media-mode request | Could bypass recovery cadence | No independent probe/stop |
| Disabled output or failed media-tool validation | Could stop fallback | Original owner retained |

The 24-hour elapsed interval is fast-forwarded, not a wall-time soak. Policy probe
count and real-child coordinator ownership are separate tests, not a claim of
2,884 actual OS probe launches or measured DeckLink stability. Hardware testing is
pending an owner-approved window. P2-12 owns epoch acceleration/stable-media reset;
P2-13 owns physical stop/ghost-audio qualification.
