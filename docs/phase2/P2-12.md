# P2-12 — reconnect epochs and retained retry debt

## Root cause and test-first evidence

The fast publisher supervisor discarded `ObserveConnected` twice, then rewrote
the retry deadline every second merely because REST remained connected. It also
reset restart debt at the first live output frame. The first task commit af59063
reproduces both defects through the real coordinator: the delayed retry becomes
immediately due without a new epoch, a consumed epoch is reused, and retry count
3 becomes 0 at the first frame. All three assertions failed before implementation.

## Changes

- Consume the disconnect detector's confirmed return exactly once. Keep a pending
  epoch if the route semaphore is busy; do not lose it or replay it on steady REST.
- One new epoch may accelerate probe readiness, but cannot forgive failure debt.
  An old in-flight probe finishes before the one fresh accelerated request.
- REST presence stays `PublisherActive`, not `Ready` from old media metadata.
  Waiting routes cannot stop standby using cached pre-disconnect media alone.
- Retain retry debt until 60 seconds of continuous advancing unique output-frame
  count and media time, fresh progress, unchanged session and no recent classified
  anomaly. Unknown/gapped/reset evidence starts a new window. Emit a structured
  decision when debt resets. No destructive detector threshold changes here.

## Tests and measured software result

| Case | Before | After |
|---|---|---|
| Steady connected publisher | Rewrites due time repeatedly | 3,600 observations over simulated hour leave deadline/debt unchanged |
| Real reconnect with busy route gate | Transition discarded; repeated acceleration | Pending return survives gate contention, used exactly once |
| Connected REST + RTSP 404 | Repeated acceleration path | 124 actual fake FFprobe child launches in simulated hour; zero fallback stops |
| One reconnect after that hour | No epoch bound | Exactly one extra probe (125 total); no next probe for 29 s |
| First live frame | Debt 3 -> 0 | Debt remains 3 |
| Stable evidence | No qualification window | 59 s cannot reset; 60 s can; faults/session change/gaps reset window |
| Reconnect of waiting route with cached AV | Stops old owner | Owner retained until real probing |

The fake probe accepts real tokenized FFprobe arguments, emits RTSP 404 stderr and
the corresponding synthetic negative exit code, and records each launch in its
isolated temporary directory. It performs no network/hardware operation. The
hour uses injected monotonic time, not a wall-clock soak.

## Scope limits and gate rows

The stability window uses the strongest existing output counters; it is **not
proof of independently advancing input PCM or decoded input PTS**. P2-20–22 must
add those signals. An unobserved interval longer than two seconds conservatively
retains debt, even if the physical output was actually healthy. Nothing here
claims physical SDI health or closes KnownDefect R06.

The connected-404/publisher-epoch software row is covered. Combined real 0.5/1/3 s
source interruption and physical decoder/SDI recovery remain unqualified. Physical
testing, long-GOP/source-track transitions, REST schema failures, fault-detector
false positives, slow DB/controller concurrency, containment and soak remain with
their named later tasks. All seven KnownDefect assertions remain OPEN unchanged.
No production changes. PR is stacked; merge parent first and retarget to main
before owner merge. Agent does not merge.
