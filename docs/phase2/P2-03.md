# P2-03 — decision and owned-session telemetry

## Scope

Instrumentation and diagnostic classification only. No detector thresholds,
retry curve, ownership rules, source-readiness rules or FFmpeg media flags were
changed. The existing whole-host watchdog remains a known design defect until
P2-30; logging it does not make that policy safe. No production or hardware
actions were performed.

Every structured event carries UTC, monotonic timestamp/frequency and service
run ID. Decision requests and completion results share a decision ID; source
and output identifiers are run-local keyed opaque IDs. Source epochs describe
observed publisher transitions, not independently proven media epochs. Owned
sessions have GUIDs, exact OS PID/start time when queryable, process purpose,
stderr reference, progress/media-warning counters, threshold/window, alternatives
and outcome. Unknown identity or evidence remains null, never invented.

Instrumented boundaries include input/publisher recovery, connected-publisher
acceleration, retries, saved-route invalidation, inactive-source teardown,
fallback/live/standby handoffs, media-mode replacement, standby configuration
replacement/start/failure, priority yield, route persistence, supervisor
replacement, held recovery, lifecycle transitions and watchdog termination.
Requested/aborted operations remain visible; process-started is explicitly
**not media-qualified** in the new records. Existing GUI claims are not fixed
here (P2-50).

The retry delay is sampled once and used both for the decision window and the
actual deadline. Instrumentation must not consume extra random samples.

## Storage and privacy

The private `DataDirectory/telemetry` directory contains JSONL segments:

- `run-<run-id>.decisions.<segment>.jsonl`
- `run-<run-id>.router.<segment>.jsonl`
- `session-<run-id>-<session-id>.stderr.<segment>.jsonl`

Media callbacks enqueue without filesystem I/O. The queue holds at most 4096
records; each file is at most 1 MiB and the directory contains at most 512 owned
segments. Foreign files are not deleted. Owned segments older than 30 days are
removed; count limits can evict younger segments. **This is up-to-30-day retention,
not a proven 30-day minimum.** Capacity sizing/archival remains an acceptance gap.

Status exposes accepted/written/dropped/write-failure/shutdown-abandonment counts,
capacity evictions, age expirations and oldest retained segment-write UTC.
`IsHealthy` means no observed I/O/drop/abandonment failure; `RetentionComplete`
also requires no early capacity eviction. The health endpoint degrades on I/O
loss. Retention counters remain explicit in records; neither implies SDI health.

Shutdown drain is bounded to five seconds. A wedged storage operation can remain
on an abandoned worker until the OS returns, but cannot indefinitely block host
shutdown. A full queue or disk failure means evidence can be missing, explicitly
reported by counters. No software can promise durable evidence when storage is
unavailable. The watchdog drains file evidence before its best-effort DB write,
with the existing five-second total budget, before termination is requested.

Secret-bearing key/value lines are omitted conservatively, rather than guessing
quoted/escaped token boundaries. URL credentials, addresses and Windows paths
are redacted. Oversized lines are omitted. Reparse ancestors are checked before
directory creation and again before file operations. These private operational
files are **not approved public exports**; arbitrary unlabelled personal text
is not universally detectable. Public diagnostic-export R18 remains open.

Windows Application logging is explicitly filtered off even when Windows Service
hosting adds that provider. Router warnings go to its own file provider. OS/SCM
events are unaffected. Physical event-log retention has not been measured here.

## Established classification root causes

`-875574520` / `0xCBCFCB08` is `AVERROR_HTTP_NOT_FOUND`, computed as
`FFERRTAG(0xF8,'4','0','4')`, not our forced-termination code. See FFmpeg's
[error constants](https://github.com/FFmpeg/FFmpeg/blob/n8.0/libavutil/error.h)
and [tag macro](https://github.com/FFmpeg/FFmpeg/blob/n8.0/libavutil/macros.h).
The .NET Windows `Process.Kill` implementation requests exit code `-1`; see
[runtime source](https://github.com/dotnet/runtime/blob/v8.0.21/src/libraries/System.Diagnostics.Process/src/System/Diagnostics/Process.Windows.cs).
This identifies the numeric value; it does not prove every historical HTTP 404's
server-side cause.

The old classifier labelled any DeckLink `No buffered audio` line as
initialization failure. The new diagnostic classification distinguishes startup
from runtime underrun when output progress has already been observed. Runtime
underrun is not proof of encoder fault or measured receiver silence.
