## Test-first component evidence

- The unchanged R06 correctness assertion is promoted to the ordinary suite in
  this branch. A fresh progress heartbeat with unchanged counters no longer
  refreshes the parser's media-advancement timestamp. That fixes the probe; it
  does not finish the broader R06 integration requirement.
- Input video, input audio, output video and output audio have separate evidence
  states. Heartbeats cannot serve as a second failed media signal. Instrumentation
  loss is Unknown. An OS exit is definitive; two failed media measurement points
  are required for the model's automatic-recovery authorization.
- Provisional constants: suspect after 1 second, confirm after 3 further seconds,
  startup qualification 20 seconds, recovery qualification 2 seconds. These are
  starting values from the plan, **not bench-tuned jitter/GOP guarantees**.
- Stats parsing distinguishes decoder-frame provenance from post-filter and mux
  counters. A mux observation means submission, not receiver acknowledgement.
  Missing provenance, malformed records and wrong-channel records are rejected.
- Four separate current-user-only named pipes avoid mixed independently buffered
  audio/video records. Each uses a bounded line buffer. Oversized or incomplete
  records cannot invent media advancement; EOF invalidates instrumentation.
- A session connects only mapped real source tracks and their matching output
  submission points. Generated black and silent replacement tracks are excluded
  from this source-health verdict. Disposing instrumentation becomes Unknown;
  rejecting a second attachment must not close the first owner's pipes.
- Counter resets require fresh qualification rather than inheriting a stale
  high-water mark. The regression failed Unknown-versus-Failed before the fix
  (`a752d52`). Equal counters still do not constitute advancement.
- Publisher observations expire after 10 monotonic seconds. The coordinator must
  pass its own service-run clock into that policy. The wiring regression failed
  because hold remained active after advancing the injected clock (`d8d8caa`).

## Integrated software checkpoint (not a gate pass)

The selected executable is checked for the precise stats options and PCM metadata
filters using contained, bounded help commands. A successful capability result
applies to each **new** live session; it does not replace the supervisor or existing
owners. Unqualified builds remain Unknown and emit a validation warning.

The normal and fast media watchdogs no longer stop a live owner solely for stderr,
missing/stale control progress or duplicates. Confirmed failure from two independent
measurement points authorizes recovery even with publisher hold enabled. OS exit
is still definitive. Saved-source reconciliation, missing-source cleanup and
probe-driven media-mode requests cannot bypass these guards. Fresh, complete
publisher-epoch end remains the P2-23 exception. Explicit operator/configuration
changes and deliberate qualified standby-to-live handoffs remain separate actions.
Non-disruptive media-mode reclassification belongs to P2-24.

Decision evidence includes each media signal's state and monotonic age, separate
process and heartbeat states, and the corroboration result. Publisher presence is
a non-persisted UI snapshot: Live confirmed / Publisher absent / Unknown. Expiry
does not persist an Offline state. The hold confirmation now accurately states
that confirmed failure and process-exit recovery remain enabled.
