# P2-01 — repository safety and provenance

Status: in progress, not accepted. Production has not been changed.

## Safety and scope

Main is protected with PRs, strict required GitHub Actions checks `Build`,
`Main suite`, `KnownDefect`, conversation resolution, linear history, admin
enforcement, no force-push and no deletion. The owner account authors these PRs,
so required approvals is zero. Only the human owner may merge; this is procedural
because the agent and owner use the same account.

No direct-main push was attempted: a probe that might succeed would violate the
no-direct-push rule. The configured restrictions were read back from GitHub.
Actual rejection remains unverified; do not call a dry-run proof of enforcement.

The KnownDefect job deliberately fails until P2-02 supplies the strict harness.
This PR cannot pass the complete merge gate until that dependency is available.
There is no bootstrap success, skipped defect or weakened assertion.

## Reproducibility boundaries

- SDK is pinned to 8.0.425 with rollForward disabled (the SDK available for the
  reviewed baseline build). Actions are pinned to resolved commit SHAs.
- The runner OS selection is fixed to `windows-2022`, not `windows-latest`.
  **This is NOT an immutable VM-image pin.** Hosted Windows image contents still
  change. CI prints ImageOS/ImageVersion and compares two clean publishes on the
  same runner. A genuinely fixed VM image requires separately provisioned build
  infrastructure; that part of P2-01 is not claimed complete.
- Package manifests include source commit, exact SDK, per-payload length/SHA-256,
  and explicit FFmpeg qualification status/build ID/digest. They exclude their
  own bytes; the external archive SHA-256 covers the included manifest.
- No FFmpeg runtime has passed the new Phase E qualification. The record is
  intentionally `not-qualified`; tagged release publication fails closed.
- Published asset upload no longer permits replacement. No tag/release is created
  as part of Phase A.
- CI compares payload and manifest bytes. ZIP timestamps are not asserted to be
  reproducible; the ZIP digest identifies the delivered archive, not a rebuild.
