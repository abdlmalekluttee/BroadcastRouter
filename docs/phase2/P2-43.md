# P2-43 — prepared standby slate

## Behavior

Compose the selected pattern, four configured logos and card/port labels once
into an immutable content-addressed RGB PNG. Playback decodes/converts it once,
repeats the frame at the preset's field cadence, and retains the interlaced mode,
TFF marker and explicit zero-valued 48 kHz stereo PCM. Preset mute remains
authoritative. Clock-enabled ports show a live clock/date; clock-disabled ports
show a one-hertz blinking square. A purely frozen slate is never used.

Prepare before stopping the previous valid standby. Rendering has a bounded
owned helper; cancellation, bad pixels, missing files and cache exhaustion keep
the previous owner and show a bounded-retry failure. Revalidate port intent,
media capabilities, settings signature and supervisor generation after rendering.
Logo content changes at an unchanged path invalidate the cache.

Preparation is tracked/pollable work, not a sequential renderer wait in settings
saves or the main reconciliation cycle. A save persists the accepted configuration
while the UI reports preparation/retained-output status. Only a completed,
still-current artifact can authorize replacement. There is at most one pending
helper per port, including cancellation cleanup. Supervisor shutdown cancels and
drains render helpers; source stop sees an admitted standby start before its first
await. Healthy progress from a retained slate cannot clear a broken replacement's
retry/circuit debt. PNG decoding and `png_pipe` demuxing are validated separately
from PNG encoding and image2 muxing.

Published artifacts are immutable and are not automatically deleted. The
256 MiB cache refuses new preparation when it cannot reserve the bounded render
space. Cleanup requires a maintenance window with no owners referencing the
removed files; never delete a live cache to clear an alarm. Old artifacts may
therefore consume space until maintenance. Temporary renders are separately
owned and cleaned. PNG checks include dimensions, CRCs and actual bounded pixel
decompression, not file existence alone.

## Evidence boundaries

The original graph is retained for a local baseline. Private original labels,
logo and commands are not published. Local null sinks cannot reproduce native
DeckLink teardown behavior or prove physical audio silence.

Initial attempts accidentally selected HD bars through a wrong private-fixture
enum value. Their matching filter graph did not prove the input matched. They
are retained as supplemental HD-bars observations, **not exact-production
reproduction**. One direct eight-output barrier exceeded one second (1002.292 ms
before handle disposal). Initial CPU readings also used cached process data and
are invalid. A new baseline-input guard rejects the fixture mismatch; required
testsrc2 cohorts use corrected input and refreshed samples. Exact results and
full-suite/review status must be recorded before readiness. No failed attempt was
discarded or reclassified as passing.

The FFmpeg source places keyboard handling after the scheduler wait and joins
workers during stop. The observed local delay was primarily after q delivery,
not its write or stderr drain. This is not proof that drawtext, logo composition
or the native driver caused the historical five forced stops.

All 390 owners exited cleanly. The original also met the local target:
**production forced-stop defect NOT REPRODUCED**. The live clock remains enabled;
its mean was about 100 ms slower than pulse at five owners and 13 ms slower at

from steady CPU intervals. No build/test workload overlapped these measurements.
No checker/FFmpeg child remained afterward. Aggregate supervisor stops include
the completed StopAsync boundary; internal phase timings and peak memory are not
qualified here. Earlier pre-review exact cohorts also had 390 clean exits and

but the table above is the final review-fixed payload.

Separate four-second lossless local captures contained 100 advancing 25 fps
frames with 40 ms PTS steps, all marked interlaced/top-field-first, and 768,000 PCM bytes per variant,
all zero. Pulse/clock captures had 2/5 distinct images respectively; the four
logos, labels, clock and date were visually inspected privately. The PNG input
produces a `gbr` color-space tag in the lossless capture despite YUV422 encoding;
these checks do not qualify colorimetric fidelity or SDI color handling. Native
playback still requests uyvy422. Midnight rollover was not exercised by changing
the developer machine's wall clock.

Historical lifecycle records identify some explicit standby owners but omit
purpose/arguments for most route-owned sessions. Association with preceding
offline-input exits is not proof of logo fallback. Their forced stops cannot be
attributed to this graph from those records alone.
