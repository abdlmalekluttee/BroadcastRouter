# P2-33 — monotonic supervision qualification

This main-based task adds tests, not a new production clock implementation. The
clock split was already wired in Phase A. No watchdog threshold, media policy,
stop budget, Windows clock or NTP setting is changed.

## What is exercised

- Actual synthetic media children and both coordinator supervision paths, with
  continuous audio/video, audio-only and intentionally sparse video. A ±2-second
  UTC step preserves the exact process ID/session and media classifications.
- After instrumented media stops advancing, no recovery at 3.9 elapsed seconds;
  at 4.0 seconds the existing corroborated-failure policy stops the owner and
  records one retry, independently of either UTC-step direction.
- Publisher freshness at 9.9/10 seconds, initial retry at one second and circuit
  cooldown at 300 seconds. UTC steps cannot renew or expire these intervals.
- Provider-backed delay/periodic timers, public snapshot dates and durable
  retry-deadline conversion/rebasing. UTC display boundaries follow wall time;
  elapsed supervision stays monotonic. Existing ±10-second cases are retained.
- An actual uncooperative synthetic child: wall stepping does not bypass or
  prolong its real elapsed graceful-stop budget; an exact held OS handle proves
  termination and the expected forced-stop lifecycle event is retained.

The fixture exposes only test utilities. Existing fixture defaults and all 136
legacy behavior cases remain unchanged. The sparse case stops only input-video
observations while actual pipe-fed audio/output evidence continues advancing.
Sparse input remains Unknown, not an invented Failed vote.

## Sensitivity evidence

The focused baseline passed 32 cases (24 new, eight existing clock cases). A
temporary local mutation made `SupervisionClock.Now` read UTC directly. It
produced 21 assertion failures, not compilation or startup failures: +2 seconds
made recovery premature at 3.9 seconds, −2 seconds postponed genuine recovery
at 4.0 seconds, and freshness/healthy classifications and UTC boundaries failed.
The original clock source was restored exactly (`git diff` empty), and all 32
focused cases passed again. The mutation is not committed.

## Ambient clock inventory

The existing test `SupervisionNamespacesDoNotReadAmbientClock` checks Application,
Infrastructure and Web/Services source on every normal run. These seven reads
remain explicitly allowed; any new direct wall-clock/Stopwatch/TickCount read
in those scopes fails that guard:

| Location | Count | Reason |
| --- | ---: | --- |
| SupervisionClock | 1 | Sole ambient TimeProvider factory at service-run boundary |
| OperatorTime | 1 | UI relative-date presentation, never a recovery decision |
| SqliteDataStore | 4 | Durable UTC audit/database metadata, never policy elapsed time |
| DeckLinkSoftwareInformationProvider | 1 | External driver-update cache, not stream recovery |

Real external-operation cancellation/reap deadlines intentionally remain elapsed
.NET timers; a frozen fake policy clock must not prevent stopping an OS child.
