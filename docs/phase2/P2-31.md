# P2-31 — bounded diagnostic persistence (in progress)

## Telemetry flush timeout

A controlled local reproduction traced repeated storage stalls to the retention
marker's synchronous durable flush, performed before **every** capacity eviction.
At 16 concurrent rotation fixtures, 16 of 24 original runs missed the existing
five-second flush deadline. Boundary tracing then located the long pauses inside
the marker durability barrier, not the asynchronous segment append. Changing the
append stream to asynchronous I/O did not remove the failure.

The earlier, untraced full-suite timeout is consistent with this mechanism; it is
not retrospectively proven to have the same cause. Private traces are retained.

The correction durably records the first loss of each category before deleting
evidence. Repeated losses update in-memory counters, checkpointed at explicit flush
and normal shutdown. A crash before that checkpoint retains a lower-bound count
and a sticky incomplete-history alarm, never a healthy history. A failed initial
durability barrier still prevents deletion. The byte cap, disk reserve and original
five-second test deadline are unchanged.

A deterministic 450 ms storage-barrier fixture failed at the explicit deadline
assertion before the correction and passed afterward. Crash-before-checkpoint,
failed-first-marker and normal-shutdown counter tests cover the durability boundary.

## Diagnostic queue

Coordinator and process/service lifecycle diagnostics now enter a bounded queue
without database I/O on their callback. Up to 2,048 queued/in-flight summary keys
are retained. A single worker commits batches of at most 32; repeated pending
events coalesce with first/latest timestamps and an explicit occurrence count.
Lifecycle keys use source and event state, not the changing process ID. Detailed
per-session records remain in file telemetry.

Queue age, peak/pending records, coalesced/dropped/failed/abandoned counts and
transaction durations are observable. Loss degrades health and raises a textual
operator alert; it is never a successful persistence acknowledgement. A flush
covers every prior admission, including older entries updated by coalescing, but
does not wait for later unrelated admissions. Cancelled flush callers do not
cancel the writer. Shutdown closes admission and allows a bounded five-second
drain after service stop events have been admitted.

Settings, routes and configuration audit still use awaited transactions. A
cancelled essential save cannot become a queued success. Optional diagnostic
batches yield if the essential writer is busy and use a one-second SQLite busy
budget; discarded summaries are counted and visible.

## Database retention and disk pressure

The diagnostic table is maintained in transactions deleting at most 1,000 rows.
Expired rows are older than 30 days; the diagnostic ceiling is 100,000 rows.
Capacity eviction before 30 days commits a sticky loss counter in the same
transaction as the deletion. That counter is restored on startup and displayed
as incomplete diagnostic history. Configuration, saved routes, route history and
configuration audit are never targets of this maintenance.

Optional diagnostic writes and pruning require the greater of 20 GB or 20% free,
plus conservative transaction headroom. Unknown capacity is a refusal, not an
assumption of free space. Legacy large rows are included in the bounded deletion
budget. No VACUUM, volume-filling test or deletion of unrelated files is used.
The guard cannot reserve space against unrelated applications writing concurrently;
it checks before and after preparing each transaction and exposes failures.
Essential state still has its existing awaited commit contract and is not queued.

A background worker makes one bounded maintenance pass per minute. Queue/storage
loss and maintenance failure remain visible independently of media health.
Tests use real temporary SQLite databases with controlled capacity readings;
ordinary routing assertions do not depend on the developer's disk capacity.

Maintenance uses a transactional row counter and an ordered retention index, not
a whole-table count/sort on every batch. The initial upgrade builds the index and
backfills the counter once before routing starts; that migration must be measured
against a consistent database copy before deployment. Every stored field and the
timestamp/category indexes contribute to the deletion-space estimate. An oversized
legacy row refuses maintenance and raises an alarm rather than silently returning
a healthy no-op or creating an unsafe large journal transaction.

A durable dirty-session marker is established before diagnostic admission. Clean
shutdown checkpoints loss and clears only its own session marker. A crash, failed
checkpoint, dropped summary, failed write or abandoned drain remains incomplete
after restart. This is deliberately conservative: a crash after the last data
write but before the clean checkpoint can report uncertainty, not falsely prove
complete history. No producer performs marker or database I/O.

Whole-branch review found four reliability gaps above. Regression tests reproduced
all four before correction. A real-provider VM-instruction test guards against
retention work scaling with the entire legacy backlog; a failed mid-transaction
history write also proves that neither the database nor coordinator publishes a
rejected route. An additional log reader can still hit the bounded 64-flush-waiter
limit under extreme concurrent reads; that minor issue remains disclosed.

## Remaining qualification

Full stress qualification is not yet complete. Independent review and its Important
correction pass are complete; 709 normal tests passed with zero skipped tests.
The long fixture now requires every synthetic child to exit successfully: an
omitted event array had caused early CLR exits before its intended admission
barrier. That fixture defect was reproduced with an explicit exit-code assertion
and corrected; earlier long runs are not accepted qualification.
This document is not a Gate D acceptance
or permission to deploy. Essential routing/settings/audit transactions must remain
durable and awaited; optional diagnostic queue admission is never a saved-state
acknowledgement. R18 remains open for Phase G.
