# P2-23 — strict management inventory observations

Scope: Phase 1 R07. This is a software-only change, not a production deployment
or a claim about real media/SDI stability. Base is disk-budget follow-up PR #73.

## Defect and behavior

The parser recursively searched arbitrary JSON for `incomingStreams`. Missing
collections silently became an empty successful inventory, while absent or
unrecognized state became disconnected. Normal/manual discovery also acted on
the first missing sample, unlike the fast monitor's two-sample confirmation.

The supported envelope now requires a top-level `incomingStreams` array. Every
entry has an unambiguous `name`/`streamName` and explicit boolean `isConnected`/
`isPublished` or known `state`. Supported textual states are active/published and
inactive/disconnected/unpublished (case insensitive). Conflicting aliases,
duplicate properties/names, invalid types and missing state reject the entire
inventory. Empty arrays remain valid. Unknown extra metadata is ignored; known
optional IP/uptime values are type-checked, with null allowed. A new upstream
schema must be qualified explicitly, never guessed recursively.

Every configured application/instance must succeed before a poll is accepted.
An empty configured scope is unknown, not evidence that all publishers stopped.
HTTP error bodies are not included in exceptions: they can contain private data.

Complete negative observations are counted once at the shared polling boundary.
Both discovery paths preserve the previous observation until two complete
negative inventories confirm a publisher-epoch end. Retained timestamps are not
refreshed or represented as new media proof. A failed poll breaks a pending
one-negative sequence. An already confirmed epoch remains available for the
P2-12 one-shot reconnect acceleration, including when its route gate is busy.
Request ordering rejects late responses from older HTTP requests. Per-source
presence generations reject results collected before a newer changed/unknown
observation. Unchanged connected samples retain their generation so a slower
probe can finish. Explicit and omitted stream entries use the same guarded
application path. Destructive fast-monitor decisions recheck their generation.

This does **not** make management presence proof of media health. P2-22 still owns
independent media evidence and bounded hold; P2-20/21 own false-positive detector
confirmation, and P2-24 owns probe expectations/reclassification.

## Review rulings and limits

- Both review findings were accepted as Important and fixed test-first; no
  second reviewer pass substitutes for the full post-fix suite.
- Actual Wowza schema compatibility, physical SDI/audio, service mode and GUI
  behavior were not exercised here. They are not implied by fake tests.
- Media-evidence TTL remains P2-22; full per-output serialization remains Phase D.
  Request ordering/generation checks are included now because this task can
  otherwise regress a healthy owner even before that broader controller work.
- No deferred minor finding was raised for this PR. Hardware Gate B remains
  BLOCKED-ON-BENCH and the rest of the Phase C fault matrix remains OPEN.
