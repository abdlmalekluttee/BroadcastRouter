# P2-32 — helper ownership and crash containment

Status: PR #86; local software qualification complete, fresh hosted correction
checks pending. Not a deployment or Gate D acceptance.

Local Release verification: 689 normal tests passed, zero failed/skipped (674
remaining, 14 standby, 1 telemetry). Build: zero warnings/errors. CI contracts:
17 passed; provenance: 12 passed. Strict KnownDefect verification observed exactly
the two expected R18 assertion failures; they remain OPEN for Phase G. Hosted
CI at `f33b54a` passed every required job (longest 8m50s). Fresh whole-branch
review identified an unbounded preview-reap/drain path. Its single correction
pass is verified by three RED-to-GREEN regressions and the full 689-test run:
remaining3m47s, standby2m07s, telemetry4m27s. Exact corrected-head CI is required
before this PR becomes ready.

The crash fixture reproduced surviving preview, probe and auxiliary children and
their descendants after their synthetic server host exited. The existing live
supervisor job contained its own children but assigned them only after launch.

A small host-lifetime-job prototype fixed host-crash cleanup but failed three
normal-exit regressions: a descendant retained stdout/stderr, preview/probe waited
for pipe EOF, and auxiliary cleanup returned without terminating its descendant.
That prototype is not shipped. Every Windows helper now receives its own
kill-on-close job atomically through `PROC_THREAD_ATTRIBUTE_JOB_LIST`. Creation is
suspended until the managed owner holds the exact OS process handle. The host is
not a job member; each helper's descendants inherit that helper's membership.

Only three standard pipe handles are inherited through an explicit HANDLE_LIST.
The job handle is not inheritable. Managed anonymous-pipe wrappers own the server
ends, and local child-end copies close on both success and failure. On parent
exit, closing the helper job clears descendants before draining redirected output.
Explicit forced job termination uses exit code -1 rather than reporting success0.

The launcher passes Windows CRT-quoted ArgumentList tokens directly to
CreateProcessW, never a shell. Unicode environment, selected working directory,
explicit stream encodings and hidden-window behavior are covered. Alternate
credentials and shell/raw-string commands are refused, not silently ignored.
Platform/default stream encodings preserve the existing Process convention;
tests using UTF-8 explicitly select it on both ends.

Preview cleanup now has a five-second reap deadline and a two-second stderr-drain
deadline. A reap that ignores cancellation cannot keep the preview control gate
forever; disposal runs in `finally`. Timeout or failed drainage produces a Failed
snapshot, not a successful Stopped claim. A replacement requested during that
failed cleanup is refused. Three controlled regressions failed at their original
completion/status assertions before correction, then passed; exact held process
handles also confirm termination in the real preview-reader fixtures.

Tests exercise actual synthetic child executables, successful/nonzero fast exits,
independent parallel jobs, host crash, descendant pipe holders, cancellation,
argument quoting, unrelated inheritable handles, repeated failed launches and
forced-exit classification. A handle-allowlist mutation made the unrelated-handle
test fail as intended. Four older reflection-based fixture drivers were adapted
to the owned-process wrapper without changing their behavioral assertions.

No hardware, production service, driver, user account or OS configuration changes
are part of this PR. Native Windows behavior still requires supported OS and
Session 0 qualification; a local synthetic process test is not a physical DeckLink
or service-deployment certificate. Guard PR83 must remain in front of launch and
controller-lifetime PR84 must retain its shutdown admission boundaries at merge.
